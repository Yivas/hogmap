# Core contract

The library separates the in-memory `index`, `filter`, `scan`, `synthetic` and `treemap` modules from the Windows metadata engine (`scan_win`) and drive queries (`volume`). The engine reads directory metadata, never file contents. The separate egui/eframe 0.35.0 desktop consumer remains independent of these engine APIs.

## Metadata index

`Index` stores a flat, append-only list. Each entry has an opaque ID, a parent, one native name, kind, optional logical/allocated byte counts, optional file identity and a pending/complete/partial/inaccessible/stale state. IDs belong to one index snapshot; they are not persistent identifiers and must not be carried across snapshots. A scanner/UI transport must validate the owning scan generation before passing IDs to an index.

The stored record is compact; `get()` and `entries()` return an `Entry<'_>` value whose name borrows the index as `&OsStr`, not a separately allocated name. `EntryId` uses a nonzero `u32` (four bytes, including `Option<EntryId>`); `position()` is a zero-based dense slot valid only in that snapshot. The parent uses that same four-byte representation. Two raw `u64` sizes retain their independent presence bits, so `None`, `Some(0)` and `Some(u64::MAX)` remain distinct. One byte packs kind, state and presence flags. An identity slot is a `u32`, with `u32::MAX` meaning absent; only entries with identities occupy the side vector. Side identities store three `u64`s (volume and both halves of the file ID), avoiding `u128` alignment padding without losing any bits.

Names occupy one append-only byte arena. A `NameRef` is only a `u32` slot, not an offset/length pair or proof of owner provenance. The arena privately stores the cumulative end of each whole name in a `Vec<u32>`. Resolving a slot takes its end and the prior end (or zero) from that arena's own table. A same-number slot from another or expired arena therefore selects this arena's whole name; an out-of-range slot panics on checked table indexing before any unsafe operation. Slot values never supply byte boundaries and never enter the scanner transport.

The private `name_arena` module permits one unsafe operation: reconstructing `&OsStr` from the exact whole-name bytes originally copied from `OsStr::as_encoded_bytes()` in the same process. Appending and vector reallocation preserve earlier bytes and ends, and Rust borrowing prevents mutation or destruction while a returned view is live. Equal consecutive ends safely represent an empty name inside the arena (the index still rejects empty components). Adjacent lone surrogates remain separate names. The arena is not a serialized format. `IndexError::CapacityExceeded` rejects an insertion before mutation/narrowing if the byte arena or name count would exceed `u32::MAX`, an entry ID would exceed the nonzero-u32 range, or the identity side table would consume its reserved absent slot. These representation ceilings are not a total process-memory budget; allocation failure can occur much earlier.

An entry can only be appended below an existing directory. Its name is one component, not an absolute path: empty names, `.`/`..`, NUL, separators, colons and names longer than 255 UTF-16 units (the Win32 maximum component length) are rejected. Native Windows names that are not valid Unicode remain intact. The index does not duplicate full paths or expose mutable entries.

`summary()` returns:

| Field | Meaning |
|-|-|
| `files` | Visible file entries, hardlinks included |
| `known_logical_bytes` | Sum of every visible file entry with a known logical size |
| `unique_logical_bytes` | Logical bytes charged once per file identity |
| `shared_logical_bytes` | Logical bytes of later hardlink entries that were not charged again |
| `unknown_size_files` | Files whose logical size is unknown |
| `complete` | Every entry is `Complete`; unknown sizes also clear it |

The byte sum alone is never a claim of completeness. Zero-byte files and files with unknown sizes remain distinct. Overflow returns an error instead of wrapping or saturating.

Logical bytes count each visible hardlink entry in `known_logical_bytes`. `unique_logical_bytes` charges a file identity at the first entry that has that identity and a known logical size; later links only add to `shared_logical_bytes`. A link whose size is unknown does not consume the charge for its identity. Identity-less files, such as on a filesystem without stable file IDs, are counted individually. Before any explicit conflict resolution, `known_logical_bytes == unique_logical_bytes + shared_logical_bytes` when no sum overflows. After resolution, add `summary_for(Logical).resolution_delta_bytes` to the listed known total to retain that equality. None of these values is physical, allocated or recoverable space, and directory-provided sizes are not added again to the file total.

`summary_for(metric)` returns the same shape for `SizeMetric::Logical` or `SizeMetric::Allocated`, with generic field names so allocated bytes are never labelled logical:

| Field | Meaning |
|-|-|
| `metric` | Which byte count these totals weigh |
| `files` | Visible file entries, hardlinks included |
| `known_bytes` | Sum of every visible file entry with a known size for this metric |
| `unique_bytes` | Bytes charged once per file identity |
| `shared_bytes` | Bytes of later entries that reused an already charged identity |
| `unknown_size_files` | Files whose size for this metric is unknown |
| `identity_missing_files` | Known-size entries of this metric without an identity, counted individually |
| `conflicting_identities` | Unresolved identities whose known samples for this metric disagree; each identity counts once |
| `resolution_delta_bytes` | Signed correction to first listed charges; `known_bytes + resolution_delta_bytes == unique_bytes + shared_bytes` |
| `complete` | Every entry is `Complete` and no file has an unknown size for this metric |

`summary()` keeps its six logical fields and its results; it is the compatible path, and the filters still receive logical bytes. `complete` covers entry states and known sizes of the selected metric only. It does not certify consistent identities, an exclusive physical attribution or a reconciliation with volume-used bytes: `conflicting_identities` and `identity_missing_files` are separate confidence indicators that a future reconciliation has to inspect. A conflict or a missing identity is not a reason to pick a maximum, recharge an identity or drop a record. Only the explicit verified-handle post-pass described below can replace a conflicted identity's charge.

Each metric charges independently. `Some(0)` is a known size and consumes that metric's identity charge; only `None` leaves the charge for a later entry, and an unknown logical size never skips a known allocated size. A known size without an identity cannot be deduplicated, so it is charged on its own and counted in `identity_missing_files`. When a later known sample of an already charged identity differs, that identity is marked conflicted once for that metric, the first charge is kept, later samples add to `shared_bytes`, and the stored observations are neither rewritten nor discarded. Unequal samples are therefore not permutation-invariant: whichever entry is charged first keeps the charge. Overflow is tracked per metric, so an allocated overflow does not poison logical totals or the reverse, and insertion still reports it through the summary query instead of rejecting or losing the record.

The index maintains these totals as entries are appended, so `summary()` does not walk the entries. Keeping them current costs one accounting row per file identity, holding the key and, per metric, the first known sample and a conflict flag, plus a count of incomplete entries. The row is a sparse ledger: entries without an identity or without a known size allocate nothing. The key uses the three-u64 identity representation.

After a finished scan, `conflicting_identities()` lists each still-conflicting identity once across both metrics. `apply_authoritative_sizes(identity, sizes)` corrects each metric independently when that metric already had a charge and the authoritative size is known. `IdentityResolution` reports Applied, MissingCharge or UnknownSize per metric and whether any conflict remains. Unknown listed sizes are not filled. All arithmetic is checked before either metric changes; an overflowing correction fails atomically. Known/shared bytes, unknown counts and raw entry sizes remain listed observations. Only unique charges, unresolved-conflict counts and the signed resolution delta change. Thus `known + delta = unique + shared` holds per metric, including zero and negative corrections.

Overrides occupy a sparse identity map, not fields on every stored entry or another full identity ledger. The first applied correction seals insertion: `insert` returns `IndexError::ResolvedSnapshot`; a rescan must create a new index. `set_state` remains allowed. Layout uses the corrected size at the same first already-known entry that owned the charge, so summaries and geometry agree without moving the charge to another hardlink. Filters and `Entry.sizes` still read the listed values. `ScanReducer::finished_index_mut()` only exposes mutable post-pass access after a Finished terminal was consumed. The desktop initiates the separate asynchronous pass; enumeration producers never mutate this index.

`conflicting_identity_count()` maintains the union of unresolved identities in constant time. `conflict_candidates()` reads a sparse map retaining at most 4096 representative entry IDs, selected at each identity's first disagreement, not necessarily its first listed hardlink. Ordinary stored entries gain no fields. Excess conflicts remain accounted for even when no name is retained. `memory_estimate()` includes the original charge table, sparse override map and sparse conflict-name map in `charged_identity_bytes`. It is constant-time and reports live record/name bytes, their allocation capacities, whole-name boundary-table capacity, identity-vector capacity and an approximate allocation for the per-identity accounting table (SwissTable buckets/control bytes inferred from capacity, including the full key **and** value size rather than the key alone). Allocator headers, alignment rounding outside the record, process/runtime code, thread stacks and retained freed pages are excluded. The estimate is not working set, committed memory or a measured peak.

`MetricSummary::apparent_bytes()` returns the checked u64 area total without adding stored state. The invariant remains `apparent = known_bytes + resolution_delta_bytes = unique_bytes + shared_bytes`, evaluated with signed intermediate arithmetic and checked u64 conversion. `known_bytes` is still the unmodified listed sum; `unique_bytes` is still the corrected first known charge per identity (identity-less entries individually); `shared_bytes` is still the unmodified sum of later known names. None of these existing fields is silently redefined. Files, unknown counts, missing identities, unresolved conflicts, resolution delta and completeness keep the meanings in the table above. An apparent total outside u64 returns SizeOverflow, even if unique and shared separately fit. Layout and the tree/free/reserve geometry use that representable apparent total. The estimated difference separately uses corrected unique allocated bytes; coverage remains independent.

## Name and logical-size filter

`Filter::parse` either creates a complete valid filter or returns a typed error. A consumer must keep its previous valid filter when parsing fails. `evaluate` returns `Yes`, `No` or `Unknown` for one file; directories are context for matching descendants, not independent file matches. Filtering never changes the index or decides what gets scanned.

| Expression | Meaning |
|-|-|
| Empty | All files |
| `*.jpg` | Whole file name ending in `.jpg` |
| `|*.jpg` | Exclude those names |
| `>100mb` | Logical size strictly greater than 104857600 bytes |
| `*.jpg;>1mb` | A JPG with logical size strictly greater than 1048576 bytes |
| `*.jpg;*.png;>1mb;|draft*` | JPG or PNG, larger than 1 MiB, excluding names starting with `draft` |

Positive name masks are OR-ed. Every exclusion and every size condition must also pass. `*` matches zero or more characters, `?` exactly one Unicode scalar. ASCII letters are case-insensitive; other Unicode characters compare literally. This is not a claim of Windows-wide Unicode case folding. If a native name cannot be represented without loss, a name-dependent result is `Unknown`. A conclusive failing size or name condition still returns `No`.

Size conditions accept `<` or `>`, a non-negative decimal integer and `b`, `kb`, `mb`, `gb` or `tb` (case-insensitive). These legacy suffixes use powers of 1024; they do not mean decimal SI units. Comparisons are strict. The metric is always **logical bytes** in this first unit, not an implicit choice between logical and physical size. Unknown size returns `Unknown` when the other conditions do not rule the file out.

The parser accepts outer whitespace on each condition. It rejects empty conditions between separators, missing/unknown units, overflow, fractional/negative thresholds, paths, tag/attribute/date operators and unsupported syntax. An expression is limited to 4096 UTF-8 bytes and 64 conditions. It does not use regular expressions or expand filesystem paths. Literal name characters other than the reserved operators retain their literal meaning.

The desktop binary uses this result to highlight matches, dim non-matches and distinguish unknown decisions without changing geometry or totals. Directories keep the strongest descendant result as context (Yes, then Unknown, then No). Invalid input keeps the last valid highlight. Filtered geometry with separately labelled totals is not implemented.

## Scanner contract

A producer emits a `ScanEvent` tagged with a `ScanGeneration`. Node keys are opaque `NodeKey` values, local to that generation. The payloads are plain data: no `EntryId`, `io::Error`, closures or shared references, so a future elevated NTFS worker can send the same events over IPC while the UI process keeps the index.

Each `ScanRecord` carries a key, an optional parent key, one native name, kind, optional logical/allocated sizes and an optional file identity. The root record has no parent and must be a directory. The producer must emit a parent before its children. A record whose parent is unknown is counted as an unknown-parent diagnostic and is not buffered for later resolution; the same applies to a duplicate key. The consumer never panics on malformed records and never silently discards them.

The record contract has no attribute field. The Windows engine classifies attributes and reparse tags internally without changing the transport; its separate counts-only `ScanReport` exposes skipped entries and degraded enumeration.

Events are:

| Event | Meaning |
|-|-|
| `Batch` | Records and directory outcomes, capped by combined item count and estimated payload bytes |
| `DirectoryDone(key)` | That directory's immediate children were enumerated; not its complete subtree |
| `DirectoryFailed { key, code }` | The directory could not be enumerated; `code` is producer-defined |
| `Progress` | Coalescable activity counters; no total or percentage |
| `Terminal(Finished/Cancelled/Failed(code))` | Exactly one, after all producer work |

`Batch` carries `records()` and `outcomes()` (`DirectoryOutcome { key, code: Option<u32> }`). A reducer applies records first, then outcomes; each outcome follows all immediate child records of that directory. Both collections count toward `MAX_BATCH_RECORDS` and `MAX_BATCH_BYTES`. An otherwise empty batch accepts one oversized record instead of dropping it. Standalone directory events remain accepted for compatibility and protocol tests; both built-in producers batch their outcomes.

`event_channel` uses a bounded Mutex/Condvar queue (default 16 events, each at most one batch) with `ScanSender`/`ScanReceiver`. `ScanCancellation::cancel()` sets its atomic flag and notifies registered channel/work-queue waiters. Essential sends block without sleeping or polling and return on cancellation or receiver disconnect; dropping the receiver clears queued events and wakes senders. The notification epoch lock closes the check-to-wait race. Progress may be dropped when full. Exactly one terminal is sent after producers finish, ignoring cancellation but respecting disconnect. Consumers must drain to terminal/disconnect or drop the receiver; cancellation alone does not interrupt terminal delivery. Transport can carry a repaint callback; event payloads remain plain data.

`ScanGeneration` only separates sessions. It does not authenticate a producer and is not a security control. Nothing here defines an IPC transport: before one exists, the consumer must enforce a total node and byte budget for the whole scan, a maximum component length of 255 UTF-16 units and an authenticated, restricted channel. Per-batch caps bound one message, not the index.

`ScanReducer` owns one fresh index for its generation and maps node keys to entry IDs. Built-in producer keys use a vector of four-byte optional IDs, accepting bounded out-of-order keys. Its length cannot grow beyond twice the accepted key count plus `MAX_BATCH_RECORDS`; vector spare capacity is additional. Sparse keys use a map fallback instead of allocating up to an arbitrary producer-supplied integer. Both stores are released at terminal/disconnect; `memory_before_release()` retains only the index/key byte estimates at that point (not their peaks). Directory pending status lives in the entry state rather than a second set; terminal/disconnect scans the index once to mark pending directories partial. Events from another generation are counted as stale and ignored before their keys are resolved. `drain` applies whole batches up to a record budget plus bounded control events. `drain_budgeted` instead caps the event count and checks elapsed time between events, always allowing one event to make progress. A whole batch is indivisible and may exceed that time budget. The reducer tracks pending directories. On `Cancelled`, `Failed` or a disconnect without a terminal, every still-pending directory becomes `Partial`; on `Finished` the same transition exposes a producer that omitted a directory outcome. A channel that closes before any terminal is reported as `missing_terminal`.

`ScanDiagnostics` counts stale generations, unknown parents, duplicate keys, invalid records, unknown directory outcomes, duplicate directory outcomes, events after the terminal, partial directories, directory failures and a missing terminal. The last directory failure code is retained for a status line. These counters are protocol evidence, not filesystem errors.

## Windows metadata engine

`run_win_scan(generation, root, sender, cancel)` returns `ProducerOutcome`; `run_win_scan_with_options` also returns a names-free `ScanReport`. `ScanOptions.workers=0` selects the pure `worker_count_for` policy, capped by available parallelism (at least one). Explicit values 1–16 override it independently of that cap. The current choices are four workers for no-seek storage and four for seek-penalty storage; unknown storage uses the latter. Their evidence classes differ: the no-seek choice came from a completed, repeated-tree local worker curve, choosing the smallest count within ten percent of the best throughput; the HDD choice is **provisional**, based on the best observed directory rate across disjoint but unequal project trees, with uncontrolled cache state. The second HDD had too little comparable work to validate that choice. This is local tuning, **not a public benchmark**, a cold-cache comparison or a hardware-independent optimum.

The shared queue holds 1–1024 directories. Overflow stays on worker-local frontiers, without a per-worker correctness cap; `local_stack_capacity` is only an initial reservation hint (1–4096). On a positively identified NTFS volume with seek penalty, both shared and local frontiers are min-priority heaps ordered by the low 48 bits of the child file ID supplied by its parent listing (the NTFS MFT record number), then discovery key. Each worker compares its local head with the published shared head. Sequence bits are ignored; missing IDs from fallback enumeration follow known IDs in discovery order. The root has no listing ID. SSD, unknown-storage and non-NTFS volumes (including ReFS), or a failed filesystem query, retain local DFS and FIFO shared stealing, never interpreting their IDs as MFT positions. This ordering is a locality heuristic, not a physical-address guarantee or direct MFT access. Work remains unpublished until its record batch is sent. Heaps reuse the pending-work slots rather than retaining a second ordering index; each pending-work slot, which now also carries the child file ID, is included in the global pending-byte charge. Heap capacity/allocator slack remains outside that estimate, as with the original stacks. Each pending directory stores a key and an Arc to one native component plus its parent chain, rather than duplicating a full path. A full path is reconstructed only for active enumeration. Shared work is published after its record batch is sent. A global `max_pending_bytes` budget (default 256 MiB, clamped 1 KiB–1 GiB) charges live path nodes, Arc headers and a pending-work slot per node, including retained ancestors. Reaching it preserves the directory record, emits `PENDING_MEMORY_LIMIT_CODE` for the skipped directory and ends with that failed terminal. Reported peak bytes are a charge estimate: allocator slack, spare stack capacity, active reconstructed paths, batches and the consumer index are separate. `peak_pending_nodes` and `pending_node_struct_bytes` expose its scale. Wide ordinary directories no longer fail because of queue pressure. The legacy `local_stack_limit_hits` field stays zero and its code has no user-facing message any more; the counter that matters is `pending_memory_limit_hits`, and coverage is shown by `unknown_parent_records == 0` plus the directory counts. Worker counters in `ScanReport.workers` exclude the coordinating thread (root record, final flush, progress). The repaint waker is called after its lock is released, so it must not assume exclusivity but may touch the channel. The index remains O(entries) and needs a separate total/IPC budget. A bounded frontier/channel does not bound total process memory: large scans can exhaust a development benchmark's process-memory guard and cause paging on the system drive even when build files and temporaries are elsewhere. The compact-index observations above do not validate whole-volume scaling or certify full native-UI memory use.

### Optional origin observations

`run_win_scan_observed_with_options(generation, root, sender, cancel, options) -> ObservedScanResult` is an additive backend API. Its named result separates `outcome`, the existing `report`, and `observations: ScanOriginObservations`. `run_win_scan` and `run_win_scan_with_options` retain their signatures, behavior and counts/timings-only `Copy` report. Their path passes no observation state and makes none of the supplementary native queries described here. The desktop uses the observed API; the benchmark defaults to legacy and explicitly opts into observations. Origin facts remain separate from the pure consumer eligibility evaluator and are never persisted. Existing operation counters do not include auxiliary observation queries/opens, although observed-mode elapsed time includes their overhead.

Observed mode preserves the legacy scheduling policy: the same existing seek-penalty hint, conditional filesystem query, worker policy (or explicit worker count), and NTFS MFT ordering when supported. These startup scheduling queries are not supplementary origin queries. At the actual root directory handle, **after** existing directory/reparse/recall safety checks and **before** child enumeration, it captures normalized GUID-path facts, `FileIdInfo` serial64 plus full fileID128, and by-handle filesystem support flags plus filesystem type in the same GetVolumeInformationByHandleW call. `ObservedFilesystem::Ntfs` or a bounded `Other` name is retained; an empty name or failed query stays typed unknown. No additional query or open is added for the name. A zero native file ID is unavailable evidence, not a trusted root identity; this does not change the generic index or the existing serial32 entry identity. Support flags describe capabilities, not absence of compression, streams, quotas or shared allocation.

A candidate volume-root **directory** is opened using the normalized GUID root with its trailing slash. `RootScope::WholeVolume` requires a normalized root path plus matching directory/root serial64 and ID128. `Folder` requires a non-root normalized suffix, a consistent GUID namespace and distinct directory/root IDs on the observed volume; otherwise scope is `Unknown` with an issue. A drive letter, Home location, size or unequal GUID strings alone is not a scope proof. Identities are opaque and redacted in Debug; normalized paths/GUID names remain private to the capture and are dropped before return. They never enter `ScanReport`, event payloads, logs or persistence.

Every directory handle opened by the observed traversal contributes to `DirectoryNamespaceObservations`. Safe handles first query `FileIdInfo` and compare serial64 with the captured root: `serial64_same`, `serial64_different`, and `serial64_unavailable` are separate counts. Zero file IDs and failed/absent root evidence never count as same. A serial64 match is strong local evidence, **not a GUID-name proof**. On mismatch or unavailable comparison only, the worker attempts a normalized GUID-path query using its reusable buffer. `guid_on_serial_mismatch` and `guid_on_serial_unavailable` count these fallback attempts (including failed/cancelled attempts); `same_guid_name`, `different_guid_name_unproven` and `unavailable` describe their results. A different GUID name may be an alias, not a proven foreign volume; a serial mismatch remains counted even if its GUID fallback matches. Handles rejected before observation because of safety/metadata/cancellation remain `not_queried`. This is not a retained per-entry list or proof that serial32 equals serial64. No file is reopened for these facts. Auxiliary metadata-only volume-root handles are not traversal handles. Path-based fallback is still reported by `ScanReport`; observations of an opened directory do not authenticate a later fallback path lookup or remove ancestor-replacement races.

The sidecar retains the scan generation, wall-clock start, root capture time and worker-join boundary. `before` is an origin-bound Actual* capacity sample taken before root enumeration, not the chooser's drive listing. `after` follows worker completion and revalidation of the retained actual root handle's identity and normalized path. Each capacity query uses the derived GUID root, with fresh root-directory identity/namespace checks around the path-based query. Query/conversion failures preserve typed issues and unknown bytes; failed binding checks return an origin issue instead of plausible capacity. `Some(0)` remains known. Cancellation or scan/transport failure known before sampling, or missing capture, omits completion queries explicitly. A later cancellation/disconnect can race with synchronous calls or terminal delivery; a captured endpoint remains a timed metadata observation, not proof of successful delivery or scan coverage. Supplementary failures do not discard compatible scan records or alter its terminal.

The retained root handle is duplicated only in observed mode, owned by the capture and released before returning the sidecar. Workers snapshot an immutable, reference-counted capture under a short mutex; every supplementary native query runs outside it, and only counters/results are merged under the lock. Each observed worker owns one reusable 32768-unit UTF-16 buffer; legacy allocates none. Root capture and the before sample still finish before publishing children, and completion runs after all joins. Post-enumeration validation and capacity queries run before the terminal event: a slow or blocked network/filesystem metadata query can delay that terminal in observed mode only; legacy mode is unaffected. Supplementary calls check cancellation between operations; in-flight synchronous calls still cannot be interrupted and have no timeout. Source times are wall-clock observations and can regress; callers must inspect their ordering. Endpoint identity/name agreement and even equal capacity samples do **not** prove no intervening change, a common atomic snapshot, exclusive physical attribution or comparability. The consumer evaluates these facts separately; they do not themselves prove a snapshot or authorize an inaccessible-space block.

Local Windows metadata-only activation on a tiny owned directory verified `Folder`, three matching serial64 traversal observations with no mismatch/unavailable/GUID fallback, by-handle support flags, GUID-root Actual* samples before/after and unchanged identity/name at endpoints. The same production capture helper classified its volume root as `WholeVolume` by **metadata only**, without enumerating the volume. Pre-cancellation produced no observed directory opens/end query; a missing root kept its directory failure and explicit unknown origin. Binding-output negative cases cover unavailable/zero/changed identities, ambiguous GUID names and failed/incoherent capacity. They are not runtime reproductions of mount replacement, network/UNC failure, zero-ID providers or quota/pool behavior. Independent native/DPI/UI acceptance remains separate.

### Observed-scan cost

The headless `scan_bench` example uses the legacy API by default. Set process-local `HOGMAP_BENCH_OBSERVED=1` to exercise the observed API and print anonymous namespace counters; the synthetic-million mode remains unchanged. ### Explicit conflict reread

`reread_identity_conflicts(&mut Index, root, &ScanCancellation) -> ConflictRereadReport` is a separate, reusable post-Finished API. The producer cannot mutate the consumer-owned index. The observed headless benchmark calls this synchronous convenience API. The desktop shares its native logic through `ConflictRereadPlan` and `ConflictRereadBatch`; legacy enumeration and ScanReport are unchanged. The caller supplies the original scan root and must wait for Finished. The report contains counts, typed issues, signed charge changes and start/finish times, never paths or identities.

The index retains at most `MAX_CONFLICT_REREADS=4096` representative conflict names per snapshot, without scanning all identity rows or entries on the UI thread. A representative is the listed name at its identity's first disagreement. Selection order at the cap is unspecified; no other name is retried. Excess identities are reported as LimitExceeded and remain conflicted. `ConflictRereadPlan::prepare` reconstructs native paths with a time budget checked between ancestry/path components. `reread` runs the existing verified metadata operations without borrowing the index. The owner applies the returned batch with a budget between identities, only to its matching finished generation. Temporary selection/path storage is bounded; paths retain native names and the existing Win32 UTF-16 length limit. Only conflicting file names are opened; root metadata is queried once for the binding. No individual file opens are added to ordinary enumeration.

Ancestor attributes are checked conservatively before opening. File access is FILE_READ_ATTRIBUTES, share read/write/delete, OPEN_REPARSE_POINT and OPEN_NO_RECALL, without content access. Opened attributes must describe a non-reparse, non-recall file. `FileIdInfo` must match the full listed 128-bit ID; BY_HANDLE's serial32 must exactly equal the existing entry volume key, without truncating the native serial64. That serial64 must also match the root directory queried for this pass. Any mismatch leaves the conflict unresolved. Only then does FileStandardInfo provide EndOfFile/AllocationSize for the correction. Negative size fields stay unknown and are not substituted with zero.

Failures retain their stage/raw Windows code or a typed safety/identity/volume/size/index reason. Cancellation is checked during selection, path construction and between native operations; unprocessed identities remain conflicted. Calls are synchronous with no per-call deadline. The benchmark keeps its cancellation timer active through the post-pass, while the external guards remain unchanged. Path-based ancestor checks do not eliminate replacement races or certify every cloud provider's no-fetch behavior. Handle identity agreement does not create a snapshot.

Observed output includes conflict counts before/after, candidate/attempted/resolved/unresolved counts, issue histogram, cap, signed logical/allocated charge deltas and post-pass times. Existing capacity endpoints precede this separate pass; both the benchmark D diagnostics and the window's evaluator use corrected unique allocated bytes, independently of apparent map geometry. Neither uses a newly captured atomic capacity. Its relative times make that interval explicit. No eligibility or gray decision follows automatically.

Tests use fixed synthetic disagreements to check accounting, per-metric partial results, sealing, overflow atomicity, layout ownership and a cancelled capped pass. A native hardlink fixture checks the actual post-pass against an independent FileStandardInfo query, rejects wrong file IDs and serial64, preserves listed records and verifies cleanup. Its conflicting listed sizes are deliberately synthetic; a deterministic genuine NTFS stale-hardlink-entry disagreement has not been reproduced.

### Enumeration and capacity

The primary path opens **directories only** with `CreateFileW`, `FILE_LIST_DIRECTORY | FILE_READ_ATTRIBUTES`, all three share modes, and `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_OPEN_NO_RECALL`. Root components, including the selected directory, are checked once with `GetFileAttributesW` before the first open. Every child listing is classified from its supplied attributes and reparse tag before scheduling; ordinary queued descendants no longer repeat a path-based `GetFileAttributesW`. After each successful open, `GetFileInformationByHandle` supplies the volume serial and attributes of the **opened object**: directory, reparse and recall bits are checked before enumeration. The root and any opened object observed as reparse also require `GetFileInformationByHandleEx(FileAttributeTagInfo)` to classify the current tag; if that query is unsupported (some redirectors and filters), an object whose handle attributes show a reparse point is skipped with the reparse code, never enumerated or followed, while an ordinary root keeps the handle attributes, as before, and recall bits are still checked. Ordinary non-reparse descendants need no separate tag query. These checks do not validate identity against the earlier listing or eliminate ancestor-replacement races. The path-based fallback retains its directory attribute check before wildcard enumeration and again after an empty match. `GetFileInformationByHandleEx(FileIdExtdDirectoryInfo)` enumerates children in a 64 KiB, 8-byte-aligned buffer. The parser checks header/tail bounds, UTF-16 byte length and aligned, forward `NextEntryOffset` values. `ERROR_NO_MORE_FILES` is the normal end, not every failed call.

Each child receives `EndOfFile` as logical size and `AllocationSize` as allocated size. A nonzero 128-bit file ID is preserved in full with the directory's volume serial as identity. An all-zero file ID becomes `identity=None` at this Win32 boundary: [MS-FSCC FileIdExtdDirectoryInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/36172f0b-8dce-435a-8748-859978d632f8) requires that value to be ignored when the filesystem does not support 128-bit IDs. It means unknown identity, not a shared hardlink. The record, native name, kind and sizes remain intact, including known zero sizes; identity can be unknown while allocated size stays known. Such known-size files are charged individually and counted in `identity_missing_files` independently for each metric. Missing identity does not itself clear size/state coverage (`complete`); coverage and identity confidence remain separate. Negative sizes stay unknown. Files are not reopened. Hardlink identity is charged once by the index; with parallel enumeration, which name gets the first charge is not deterministic. Allocated bytes are metadata observations, not recoverable space or a reconciliation with volume-used bytes. The small native-fixture observations below do not validate general compressed/sparse/ADS attribution.

A local Windows native-fixture check (2026-11-08) exercises the actual `run_scan` → events → reducer → index path with four owned files. The normal file contains 1 MiB of deterministic bytes; the compressed file has compression enabled before writing 1 MiB of zeros; the sparse file has a 1 MiB logical extent with 4096 bytes written at offset 512 KiB; the fourth file has an empty default stream and a separate 65536-byte named stream. All construction handles are flushed and closed before observations. Compression inherited by a new fixture file is cleared on that file only before selecting its intended mode. No analyzed files, parent-directory attributes or volume settings are changed.

The regression checks names, kinds, states and lengths, and compares each indexed allocated value with the raw `FILE_ID_EXTD_DIR_INFO.AllocationSize` captured by a separate native directory enumeration. That test-only oracle uses the binding directly, not the scanner parser, child conversion, reducer or scanner output. It checks value transport, including known zero and negative-as-unknown, without asserting universal equality between different allocation APIs. [`GetCompressedFileSizeW`](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getcompressedfilesizew) has distinct compressed/sparse semantics; [`FileStandardInfo`](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_standard_info) reports handle allocation. [Streams have their own sizes and compression/sparse state](https://learn.microsoft.com/en-us/windows/win32/fileio/file-streams). Agreement in this fixture does not prove all-stream totals, exclusive physical storage, recoverable space or comparability with global volume capacity.

The native regression prints anonymous measurements and capability omissions with numeric errors. A portable test pass can still leave requested modes unverified if the filesystem rejects them: `allocation_verification_complete=1` is emitted only after raw-field fidelity assertions and requires compression, sparse, named-stream creation, primary enumeration and known allocation for all four files. Genuine fallback retains unknown allocated size and identity rather than substituting a handle measurement. The local run completed all modes and verified cleanup of its uniquely owned temporary directory; real non-NTFS fallback remains untested.

Unsupported operations (`ERROR_INVALID_FUNCTION`, `ERROR_NOT_SUPPORTED`, `ERROR_INVALID_PARAMETER`) before the first successful enumeration buffer use `FindFirstFileExW(FindExInfoBasic, FindExSearchNameMatch)` and `FindNextFileW`, without a per-file open. The fallback reports its count and last triggering code. It preserves logical size but returns **identity=None, allocated=None**, because `WIN32_FIND_DATAW` provides neither. A failure after entries were emitted does not restart enumeration and duplicate records. Empty wildcard results are accepted only after checking the directory again. Access denied (5), file/path not found (2/3), sharing violation (32) and other errors become `DirectoryFailed` with the original Win32 code, never a silently empty directory.

Names stay native `OsString`/UTF-16, including unpaired surrogates. Dot entries are omitted; invalid index components (including over 255 UTF-16 units) are counted in `invalid_names`. FFI paths are absolute and use `\\\\?\\` (or `\\\\?\\UNC\\`), allowing paths beyond 260 characters without relying on the registry opt-in. Device namespaces are rejected. The root record uses its last valid component, or `Volume` for a drive/share root; callers retain the actual selected path separately.

No reparse entry is traversed. Cloud tags `IO_REPARSE_TAG_CLOUD` through `CLOUD_F`, or either `FILE_ATTRIBUTE_RECALL_ON_OPEN` / `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`, conservatively prevent opening/traversal. The shared EA/RECALL_ON_OPEN bit alone is treated as a safety exclusion, not proof that an entry is cloud-backed. Skipped records have unknown sizes. Skipped directories get a coded outcome; skipped files are counted in the report because the unchanged protocol has no file-failure event:

| Constant | Code | Meaning |
|-|-|-|
| `SKIP_REPARSE_CODE` | `0xFFFFFE01` | Not followed: reparse point or observed reparse ancestor |
| `SKIP_CLOUD_CODE` | `0xFFFFFE02` | Not opened: recall attributes or cloud tag |
| `LOCAL_STACK_LIMIT_CODE` | `0xFFFFFE03` | Legacy traversal-limit code; no longer emitted |
| `PENDING_MEMORY_LIMIT_CODE` | `0xFFFFFE06` | Not enumerated: global pending-directory memory budget exhausted |

The reducer currently maps every `DirectoryFailed` to `Inaccessible`; a consumer must interpret these producer-defined codes as **not followed**, not necessarily a permission failure. Keep the report alongside the snapshot so file skips, invalid names, fallback and resource-limit truncation remain visible.

Parents are appended under the shared output lock. Child directories stay unpublished until the batch containing their records has been sent, so another worker cannot overtake a parent. Outcomes join batches after immediate children, not after the whole subtree. The root is flushed before workers start. Batches flush around 2000 combined items, at the byte cap, after 40 ms of active production, before a worker would wait without runnable local/shared work, when an idle worker needs unpublished work, and at the end. Outcomes alone do not force a flush. Idle workers wait on a condition variable without a timeout; push, cancellation and shutdown notify them. Essential sends use notification-based channel blocking, never sleep/retry loops. Synchronous I/O still has no cancellation deadline. One terminal attempt follows **all worker joins**, with the drain-or-drop requirement. `ProducerOutcome::Finished` denotes transport completion and can accompany a failed terminal.

`ScanReport.mft_ordered` exposes the selected scheduling mode without paths or filesystem names. `ScanReport.workers` contains accumulated open/enumeration/attribute-check (root and fallback paths only) /send-blocked/idle-wait times and counts, directories, records, batches and channel-full observations. Worker times overlap and must not be summed as scan wall time. Relative timestamps cover first open, first batch sent, last outcome and terminal; startup volume queries precede the producer's internal timing origin. `DrainReport.apply_time` measures reducer application separately from receiving/waiting. The benchmark measures first received batch and wall time; fallback I/O timing breakdown remains incomplete. No paths or names enter these diagnostics.

`volume::seek_penalty_for` resolves a local drive volume, opens `\\\\.\\X:` with **zero desired access** and all three share modes, and sends only `IOCTL_STORAGE_QUERY_PROPERTY` / `StorageDeviceSeekPenaltyProperty`. Handles are closed on both success and failure. Unsupported paths, query failures, unexpected descriptor sizes/versions and invalid flag bytes yield unknown, not an SSD guess. This is a storage hint, not a drive-model identification or an elevation request.

`volume::list_drives` uses `GetLogicalDriveStringsW`, `GetVolumeInformationW` and [`GetDiskSpaceInformationW`](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskspaceinformationw). The capacity provider uses [`DISK_SPACE_INFORMATION`](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/ns-fileapi-disk_space_information): `ActualTotalAllocationUnits` and `ActualAvailableAllocationUnits`, each multiplied by `SectorsPerAllocationUnit × BytesPerSector` with checked u64 arithmetic. Both Actual fields describe the global filesystem at the listed volume root, without caller quotas; `Caller*` fields are never used. `free_bytes` means the API's global available filesystem bytes, not a caller allowance or an exclusive physical/free-pool claim. Other pool/reserve/committed fields are not added or subtracted into these values.

Only the documented `S_OK` result is accepted. A failed/unsupported query retains its raw HRESULT as `CapacityIssue::QueryFailed`; invalid zero unit dimensions, overflow and free greater than total have separate typed reasons. Any such problem leaves **both** capacity values unknown, never clamped or interpreted from zero-initialized output. On success, `Some(0)` remains known zero, including a full volume. Label and filesystem remain independently optional; their successful observations survive capacity failure, and unqueryable roots remain listed. There is no fallback to the [quota-sensitive total from GetDiskFreeSpaceExW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdiskfreespaceexw), partition length or raw-disk reads. Even a numerically plausible caller total/free pair would not prove global scope.

`VolumeInfo` and each origin-bound `OriginCapacitySample` additionally carry `storage_reserve_bytes` and `total_reserved_bytes` from the same query, using the same checked allocation-unit conversion. The documented `VolumeStorageReserveAllocationUnits` is per-volume storage reserve **included in** `TotalReservedAllocationUnits`; the two fields are not interchangeable and must not be added together. A base capacity failure leaves both reserves unknown with the same typed reason. A reserve-only conversion overflow leaves total/free unchanged and sets `reserve_issue=SizeOverflow`, with both reserve fields unknown. `Some(0)` is known zero, not unavailable. Reserve issues are separate from `CapacityMetadata.issue`, which continues to describe total/free. No new query, file open or privilege is needed.

The provider contract does not state a universal `free + storage_reserve <= total` invariant or a complete accounting equality with its used/pool fields. HogMap records reserve values without rejecting the otherwise valid capacity pair on that basis. It does not add reserve to `free_bytes`, infer physical attribution or subtract total reserved and storage reserve twice. The benchmark exposes the difference excluding measured storage reserve. The desktop consumes the final origin-bound sample for its separately known Free space and Reserved by Windows cells; it does not reuse the header's preliminary capacity as a scan endpoint.

`VolumeInfo.capacity` keeps `CapacityMetadata`: `source=WindowsActualGlobalFilesystem` identifies the attempted provider and scope, `captured_at` records wall-clock query completion, and `issue` distinguishes observation from failure. The root identifies the queried filesystem; the timestamp is not an atomic snapshot shared with a later scan, a stable volume identity or proof of complete attribution. Metadata stays in memory and is preserved through `DriveChoice` and background scan preparation. Existing chooser/header hover and accessible capacity details expose source, query age and any unknown reason; a backward clock change yields unknown age rather than an invented interval. No capacity/path/scan data is persisted.

The API is available from Windows 10 build 17763 and uses the existing windows-sys 0.61.2 FileSystem binding; Windows 11 x64 remains the product target. A local non-elevated Windows 11 metadata test activated this provider successfully and verified coherent global values. This is not a quota-enabled-system test: real quotas, redirectors, thin/storage-pool behavior and other OS builds remain unverified. No quota, permission or global setting was changed. The library aggregates and lays out the allocated metric independently of logical bytes, and the desktop can weigh its map by either metric (see [Desktop consumer](#desktop-consumer)). Conditional gray/reconciliation is still pending, and this provider alone does not make those comparisons valid.

`volume_root_for` uses `GetVolumePathNameW` and strips the extended prefix from its returned root. Drive queries and each directory worker's full lifetime use a thread-bound RAII `SetThreadErrorMode` guard (`SEM_FAILCRITICALERRORS | SEM_NOOPENFILEERRORBOX`) to suppress removable-device dialogs. It preserves existing mode bits and restores the previous thread mode on return or unwind; it never changes process-global error mode. There is no `WNet*` network discovery; already mapped drives may still appear. Non-Windows drive queries return an unsupported error (`volume_root_for` returns None), and the scanner sends the unsupported terminal.

The only direct binding dependency is `windows-sys =0.61.2`, enabled on Windows. `Win32_Storage_FileSystem` supplies enumeration, handle metadata and volume APIs; `Win32_Foundation` supplies handles, errors, `GetLastError` and `CloseHandle`; `Win32_Security` is required by the binding's `CreateFileW` signature even with null security attributes. `Win32_System_Diagnostics_Debug` supplies `GetThreadErrorMode`/`SetThreadErrorMode` for dialog suppression and restoration. `Win32_System_IO` supplies `DeviceIoControl`; `Win32_System_Ioctl` supplies the seek-penalty query/descriptor and IOCTL constants. No new crate is needed; no SystemInformation or Console feature is used. Unsafe code is denied crate-wide and allowed only inside `src/scan_win.rs` and `src/volume.rs` for locally justified FFI, and `src/name_arena.rs` for the whole-name accessor described above. CI rejects `allow(unsafe_code)` in any other `src` file. Cargo uses `deny`, not `forbid`, so those module-local exceptions are possible; `index.rs` itself contains no unsafe code.

Small owned Windows fixtures now compare the primary scanner's complete relative names, directory/file counts and logical lengths with an independent `FindFirstFileExW(FindExInfoBasic)` / `FindNextFileW` walk. The fixture includes nested/empty directories, Unicode, 96 sibling files and a hardlink pair: five directories including the root, 99 file names and 4585 listed logical bytes. This checks per-name enumeration agreement, not unique allocation or whole-volume totals.

A publication-gated single-worker scan also creates and deletes files and a subdirectory while the producer is active. A discovered directory removed before its open retains the actual Win32 failure code, an Inaccessible state and incomplete coverage, rather than empty success. The test checks parent-before-child records, listed-or-unknown sizes and exactly one terminal with a bounded receive wait. The scan is **not an atomic snapshot**: concurrent additions/deletions need not appear, and Finished does not mean all records describe the same instant. ## Synthetic producer

`synthetic` implements a deterministic producer over the same channel and reducer. A `SyntheticSpec` fixes the root name, directory/file counts, inaccessible directories, hardlink pairs, unknown-size files and progress interval. SplitMix64 derives every choice from the seed, so the same seed produces the same records, names, sizes and identities.

The producer emits the root first, then parents before children, reports inaccessible directories with a synthetic code that is not a Win32 error, and shares file identities for hardlink pairs. It sends a final progress summary before its terminal, even when the periodic interval is zero. It builds its plan in memory and does not touch a disk. It is a contract and layout fixture, not the filesystem scanner.

## Treemap layout

`treemap::layout` is pure. It takes an index, a subtree root, a rectangle and `LayoutParams { min_pixel_area, header_height }`, and returns placed cells. It does not measure text, draw or depend on egui.

Weights are integer apparent logical bytes per listed name. Each known name contributes, including later hardlink aliases. Only the first known entry for an identity/metric receives any authoritative correction; later names keep listed sizes. Unknown logical sizes get no area and set `has_unknown`. Known zero-byte entries also get no cell. Every placed node reports `known_sum` and `has_unknown`, and the root reports the subtree totals.

Siblings whose expected area is below `min_pixel_area` are grouped before squarification into one `NodeRef::Aggregate { parent }` cell. The aggregate keeps the member entry IDs, so it remains navigable, and its weight is the sum of its members. A directory cell shows a header when its height is at least twice `header_height`; otherwise the header collapses and the whole rectangle is content, and a `header_height` of zero disables headers. Child rectangles tile the parent's content rectangle, with area proportional to known bytes.

A directory whose subtree holds no known apparent bytes gets no cell. A folder that only holds unknown sizes or inaccessible content stays in the index and keeps its unknown flags, but the map offers no area to open. Later hardlink names with known nonzero sizes do contribute area. This is the current behavior; whether such folders deserve a navigable zero-area cell is a product decision pending window review.

Both the children vector and the subtree totals vector are indexed by dense entry position and rebuilt on every call, and hardlink charging uses one entry per identity. That keeps `layout` pure and O(n) per call: a caller that redraws should cache the layout per index version instead of recomputing it every frame.

Squarification accumulates in `f64` and converts to `f32` at the boundary. The order is deterministic: size descending, then native name, then entry ID. Layout descends iteratively, only into directories whose content area reaches `min_pixel_area`; a deep tree does not use call-stack recursion. Invalid geometry, invalid parameters, an unknown root and size overflow return typed errors instead of producing bogus rectangles.

`layout_members` opens an aggregate's selected siblings using their original IDs and descendant trees, without unrelated siblings. Members must be nonempty, distinct and immediate children of the supplied parent; invalid selections return `UnknownRoot`. The root cell is the parent context, but its totals cover only the selected members. Further aggregates keep their members and remain navigable. The desktop lowers the grouping threshold in detail views so at least one member can expand on each visit.

`layout_with_metric` and `layout_members_with_metric` take the same arguments plus a `SizeMetric`; `layout` and `layout_members` are the logical path and produce identical results. Weights and unknown handling follow the selected metric, with a correction only at that metric's first known charge: a file with a known logical size and an unknown allocated size gets a cell in the logical layout and none in the allocated one, where it sets `has_unknown` instead of contributing zero. Directory metadata is never added as a weight, the entry stays in the index, and the algorithm, IDs, native-name ordering, navigable aggregates and geometry validations are shared. The desktop calls the `_with_metric` functions with the metric chosen in View.

The pure treemap layout tiles known apparent bytes per name. The existing temporary identity set only locates correction ownership; it never suppresses alias area. The desktop separately partitions its outer map rectangle among that tree and known volume components; those components never become file nodes.

## Desktop consumer

The default `desktop` Cargo feature enables optional eframe for `src/main.rs` and `src/ui/`; the library modules never import it. `cargo test --locked --no-default-features` tests the core and Windows engine without GUI dependencies. The Windows-only binding dependency remains available without `desktop`.

The window opens a drive/path chooser without starting a scan. Its drive choices come from a single background `list_drives` task, showing “Listing drives…” while it runs. Results are cached for the session and reused when reopening; Refresh drives explicitly updates them, with at most one listing task in flight. Enumeration errors are shown without inventing capacities. Each available capacity is displayed independently, including zero free bytes; capacity-query failures retain an explicit reason alongside unknown values. A selected path must pass `std::fs::metadata` as an existing directory. Prefixes are first inspected with `symlink_metadata` to reject observed symlinks/junctions and reparse ancestors without canonicalizing through them. These checks retain the engine's concurrent path-replacement limitation.

Starting a real scan cancels and retires the previous producer without joining an unfinished thread. Repeated requests coalesce into one latest request; no replacement starts until the retired producer returns, so at most one producer is active or retired. A separate preparation task validates the path, queries `volume_root_for(selected_path)` and lists drives again before launching the scanner, so the header's label and free/total bytes come from a current query rather than the chooser's session cache. That keeps the first Start working while its initial listing is still running and gives a rescan current capacity instead of one captured earlier. “Checking path and volume…” remains visible during preparation, and invalid paths return to the chooser. The generation then increments and a named thread runs `run_win_scan_observed_with_options` with default options over `event_channel(DEFAULT_CHANNEL_CAPACITY)`. The reducer, navigation history, selection and layout cache are reset. The chooser closes, and the header displays the volume root/label and queried free/total bytes separately from map bytes. If lookup fails, the header keeps the selected root with unknown capacity. File → Explore synthetic sample uses the separate generated fixture, explicitly labelled as a sample with no capacity data. F5 and Rescan repeat the selected scan root or sample, not the currently zoomed folder, and never silently substitute the sample for a real path.

The consumer drains events for about 4 ms per frame without an event-count cap, checking time between whole events; one batch can exceed the budget. Channel sends request repaint, and a still-pending queue requests another repaint. Layout remains separately throttled. It keeps the channel bounded, signals cancellation and drops the receiver before retiring a replaced or closing producer, so a terminal send cannot deadlock shutdown. It polls `is_finished()` and joins only finished threads, including during Drop. “Stopping…” is shown while cancellation or replacement waits. A close request with threads still running is held for up to two seconds while the window keeps repainting, so returnable work finishes on its own; if a thread is still blocked after that, the window closes and Drop detaches it, so a path stuck in synchronous I/O cannot require killing the process. An in-flight synchronous Win32 call cannot be interrupted or given a deadline: it can delay a replacement or the close hold, but the UI thread does not wait in `join`. Forced teardown detaches unfinished handles rather than blocking Drop; they end when the process exits. Cancel sets its flag and visible lifecycle immediately while draining continues, and Escape or the chooser's Close while a path is being prepared also cancels that preparation. Lifecycle (Scanning, Finished, Cancelled, Failed) is separate from metadata completeness; unknown sizes and inaccessible directories do not turn a finished producer into a partial lifecycle.

Layout is cached by consumed-event version, correction revision, navigation, viewport rectangle and size metric, at most four rebuilds per second while scanning. Corrections invalidate geometry/labels without invalidating highlights, whose listed inputs did not change. Hover, selection and theme reuse geometry and fitted labels.

View → Logical size / Allocated size chooses the map metric. Logical is selected at start; the choice lasts for the session, survives a rescan and is never saved. Only one map cache exists, and the metric is part of its key: choosing the other metric rebuilds geometry and labels in the same frame, even while scan growth is throttled, so cells of one metric are never shown under labels of the other. Highlight results are reused when only the metric or location changed. Allocated means the allocation size Windows reported for each file (`AllocationSize`), labelled *observed*; it is not physical attribution, exclusive space or recoverable space. Files with unknown allocated size (for example from the fallback enumeration, which has none) get no area and keep their unknown signal; a known zero stays `0 B`. The synthetic sample derives its allocated sizes by rounding logical sizes up to 4 KiB; they are generated, not observed. Highlight size conditions stay logical in both views, and the line under the highlight field says so in the allocated view. Status text, tooltips, accessible cell labels, the empty-map message and About name the selected metric. The status detail adds, for that metric, known-size files without identity and conflicting identities, separately from coverage. If the selected metric's totals overflow, the status names that metric instead of showing zero or the other metric, and offers the other one only if its own summary succeeded; both can overflow. A layout failure is kept apart from scan errors, names its metric and clears when a metric that lays out is chosen; it does not change the scan lifecycle. Switching metric keeps history, the opened folder or aggregate member names and a selected entry. A selected aggregate survives only if the new layout groups exactly the same members under its parent. An opened aggregate keeps its member names; its caption reads “N small items” only under the metric that grouped them and “N grouped items” otherwise, with N resolved in the current snapshot. Highlight decisions use a dense vector rather than one hash entry per indexed item. Navigation stores native name components and aggregate member names in memory, not snapshot IDs, so locations can be resolved against an index without retaining its IDs. Starting or rescanning a dataset clears history and selection.

The window opens in the dark theme unless a saved choice says otherwise; both are fixed palettes, independent of the system preference. View → Dark/Light switches between them in place. The stored choice is applied before the first frame, and eframe keeps the native window hidden until that frame is painted, so a saved light theme does not flash dark. Both menu items are selectable, so AccessKit reports the active one as toggled. Theme colors are resolved only when painting and in egui's visuals; layout parameters, header height and label fitting do not read them, so both themes produce the same rectangles and labels, and switching themes never rebuilds the cached layout. Cached cells store what an entry is (directory depth, file, aggregate, incomplete state), not colors. Some states also carry a mark that does not depend on hue: a dashed inner border for partial entries, a dotted inner border for aggregates at least 24 px on each side, and a dotted header rule when a folder's total is incomplete (`has_unknown`: unknown sizes, or partial or unreadable content below it). Marks are skipped on cells under 8 px. Directories, files, non-matching entries and unknown filter decisions are told apart by fill only. The painter also hatches inaccessible entries and gives stale ones the dashed border, but the current product never shows either: an inaccessible directory has no known bytes and so no cell, and nothing produces the stale state yet. Leaf cells get a 1 px seam in a darker shade of their own fill, omitted on non-matching cells. Hover (1 px), selection (2 px, stronger contrast than hover on every fill) and keyboard focus are outlines, so they never replace the state fill; on cells under 8 px hover and selection are drawn outside the cell. Focus is a two-tone dashed ring outside the control.

Only window geometry and the theme are persisted by eframe in its application-data directory. The theme is one plain string under the `theme` key, written as `v1:dark` or `v1:light`; a missing, unknown, future-version or corrupt value falls back to dark rather than guessing. Egui memory persistence is disabled, so egui's widget and in-app window state is not stored, and names, filters and navigation are never serialized. AccessKit is enabled; map cells expose accessible labels, selection and focus. Backspace goes up, Alt+Left/Right moves through history and Escape cancels a scan; while the highlight field has focus, Escape leaves the field and the scan keeps running. Text editing retains its navigation keys. The status line shows the dataset root and the native path components, and appends the small-item count when the map shows an aggregate's members. In that member view the root cell keeps the parent directory's name and adds the same subset count, so its totals are not mistaken for the whole folder.

The consumer retains the engine's returned counts-only `ScanReport` in memory and appends it to the status tooltip and the status area's AccessKit label once the producer returns: fallback directories (and the last triggering code), reparse/cloud skips, invalid names, pending-memory budget hits, maximum queue/local-stack depth and cancellation wakeups. While scanning, the report is not yet available; a sample has no engine report. A failed terminal or drive-query `ScanError` is shown as a readable message. Producer-defined safety/resource codes retain their documented meanings rather than being described as permission errors; other Win32 codes read `error N`, and a drive-listing failure states its numeric code once as `code N`. Ordinary directory failures, including the latest code, remain in that full status detail instead of leaving a permanent red fatal-error message; terminal failures, missing-terminal disconnects and producer panics use the error line. The status area's AccessKit label repeats that full detail after the visible status text, without changing its fixed height. The highlight counter is shown only when the trimmed filter text is nonempty, following the parser's blank-expression rule. Producer completion is polled without joining an unfinished thread in the per-frame drain; no report is fabricated while it is running.

### Apparent size totals and current geometry

The window labels the selected metric's total **Apparent size**, not used space. Its exact definition is checked signed arithmetic: `apparent_total = known_bytes + resolution_delta_bytes`. This counts each listed name, correcting only the record that owns the identity charge to its authoritative size. Alias records retain their listed sizes; unknown listed sizes are not filled. There is no full per-name authoritative correction and no error bound is claimed. Apparent size can exceed disk capacity. Unique allocated bytes per identity are reported separately and are the basis of the estimated difference, not of map area.

For example, listed sizes 100 and 200 for one identity, plus an unrelated file of 50, give known 350. Resolving the charged record from 100 to 300 gives delta +200, unique 350 and apparent 550, not the fully corrected per-name sum 650. Stored observations are unchanged.

**Cell sizes and areas use that same apparent total in both views.** Every known hardlink name gets area, including in subtree/aggregate views. The correction stays with the original charged record even when another name is zoomed. Unique bytes per identity are not area weights; corrected unique allocated bytes instead feed the independent estimated difference. No duplicate accounting ledger, ordinary per-entry field, filter or persisted field is added; the squarification and small-sibling grouping rules are unchanged.

### Measured volume components, without an inaccessible-space block

`composition::evaluate` uses normalized origin facts, the selected view, allocated totals and the union of unresolved identities. Typed failures require a proven WholeVolume root, unzoomed Allocated view, Finished, origin-bound known before/after capacity and storage reserve, unchanged root identity/path at endpoints, no allocated overflow, zero unresolved identities and zero known allocated sizes without identity, no serial64 mismatch or different-GUID-unproven directories, and NTFS identified on the enumerated root handle. Unknown file sizes, inaccessible/partial directories, skips, fallback and unavailable namespace checks remain diagnostic facts, not coverage-based drawing decisions.

For each endpoint, signed i128 `D = total - free - storage_reserve - allocated_unique` uses the allocated metric's current `unique_bytes`, including authoritative identity-charge corrections. It does not subtract `apparent_total` or add the correction a second time. Checked subtraction and typed allocation failures report overflow rather than wrapping; an apparent-area overflow alone does not invalidate representable unique-byte accounting. TotalReserved is not additionally subtracted. Either endpoint D <= 0 produces a typed discrepancy, never clipped area. The status shows both endpoints, not a minimum/maximum range; unavailable inputs explain why D cannot be calculated. This eligibility does not authorize drawing D or settle the policy for unreadable folders.

Independently valid final free/reserve components need a finished, unchanged, proven whole-volume frame, unzoomed Allocated view and non-overflowed tree. A missing before sample, unresolved identity, non-NTFS type or nonpositive D does not erase a separately valid final free value. A reserve-only failure omits reserve without erasing valid free. Zero is known and gets zero area. Logical/folder/zoomed views have no volume cells.

The outer map is normalized to **allocated_apparent + known final free + known final storage reserve**, not total capacity. The tree, Free space and Reserved by Windows share one byte scale; D has no cell or implicit blank rectangle. Status, tooltips and About distinguish **Apparent size (map)** from the undrawn estimated difference against unique allocated bytes, and report **Repeated hard-link names = allocated_apparent - allocated_unique** as a separate number (the listed shared bytes). For matching endpoint inputs, `map + free + reserve + D = total + repeated_name_bytes`: the sum can exceed disk capacity by those repeated-name bytes. For example, two names of a 300-byte file plus a separate 50-byte file give apparent 650 and unique 350; with total 1000, free 250 and reserve 100, D is 300, not 0. These are different accounting bases, not a complete disk partition or an attribution of the difference to a measured cause. Unknown/overflowed repeated-name totals stay unavailable, not zero. Neutral existing theme tokens, focusable noninteractive AccessKit labels and metadata tooltips distinguish the components without adding file actions, selection or zoom.

After the observed Finished result, preparation and application use roughly 4 ms frame budgets. Only the bounded metadata plan moves to the worker; the large Index stays on the UI thread. Results carry the scan generation and obsolete ones are discarded before application. Stop/Escape cancels preparation or native rereads; verified completed observations may still be applied, while unprocessed identities retain conflicts and reasons. Rescan retires a reread worker and waits for it before launching replacement work. Close polls finished workers and preserves the existing two-second grace/detach behavior; it never joins blocked I/O. Progress and anonymous results live in the existing status/tooltip. Observations and paths stay in RAM; persistence remains geometry/theme only.

Fixed-answer std-only tests exercise gates, signed arithmetic, known zero and independent unknown components. A labelled synthetic stream through the public event channel, actual UI drain/reducer and headless egui status/map checks literal initial/intermediate/Finished counts: 1/4/6 entries, 0/2/4 files, 0/11/16 known logical bytes and 0/1/1 unknown sizes. Rendered AccessKit status labels retain those values. A deliberately omitted directory outcome becomes Partial at Finished, and a known-zero file remains distinct from the unknown file. This verifies lifecycle versus coverage, not a map repaint after every event or native-window progress. Other headless egui tests check proportional geometry in both themes, visibility, keyboard/AccessKit labels, no click actions, cancellation, stale generations and nonblocking retirement. They do not establish native visual, screen-reader, DPI or full-volume acceptance. No Inaccessible space or other residual block is implemented.

Not-yet-scanned map blocks, saved snapshots, export and alternate view modes are not implemented. The corresponding unavailable controls do not imply those capabilities exist; only the nested map, weighed by logical or observed allocated bytes, is active.

An error returned by `eframe::run_native` prints a clear message to stderr and returns exit code 1. There is no native message box, graphics fallback or claim that upstream graphics panics are caught. Real-driver fallback, DPI coverage and full accessibility testing remain separate checks.

## Verification boundary

Integration tests call the public index, filter, scan, synthetic and treemap API with synthetic metadata and fixed expected answers. They cover the filter grammar, unknown values, native Windows names, hierarchy, component length and overflow; scan generations, parent order, batching caps, cancellation under backpressure, a dropped receiver after cancellation, duplicate keys, invalid records, unknown directory outcomes, disconnect without terminal, inaccessible directories, hardlinks, unknown sizes, terminal handling and determinism; and layout containment, sibling disjointness, area conservation, proportionality, headers, aggregation, unknown sizes, determinism and a deep tree. Per-metric tests cover independent first charges, `Some(0)` versus `None`, one conflict per identity with the first charge kept, identity-less known sizes, per-metric overflow isolation and different logical/allocated geometry for the same entries and aggregate members.

`tests/navigation.rs` also exercises history across new snapshots, aggregate locations, hit testing, measured-width label fitting, highlight decisions, invalid-filter retention and lifecycle states through the binary's pure logic module. `tests/aggregate_navigation.rs` checks aggregate member layouts through the public treemap API. Unit tests in `src/ui/theme.rs` check both palettes' contrast, each theme overriding a different system preference, and the stored preference read and written through `eframe::Storage`. UI boundary tests also check volume-to-choice mapping and fresh preparation (including capacity source, exact capture time and failure reasons), existing-directory validation and producer-code messages. A module-local regression feeds the actual DISK_SPACE_INFORMATION conversion boundary with differing Actual/Caller quota fields, known-zero reserves, query failure, invalid units, incoherence and overflow. It checks that base failures leave reserves unknown and reserve-only overflow preserves total/free. A separate real metadata query asserts provider activation, known reserve fields (zero allowed), coherent total/free and a recorded capture time. The small observed fixture also checks reserve activation at both GUID-bound capacity endpoints. Headless egui tests do not establish native-window behavior.

Pure scheduling tests reject MFT ordering for ReFS/unknown storage, strip sequence bits, order known IDs before missing IDs and preserve DFS otherwise. A temporary-directory test forces the MFT policy independently of the fixture's actual medium to check parent publication, outcomes after immediate child records, one terminal and the pending budget; it is not HDD performance evidence. The public publication test also exercises an explicit sixteen-worker override.

Windows engine tests also scan only small temporary fixtures: nested and empty directories, known file lengths, Unicode names and hardlinks, normal/compressed/sparse files and a file with a named stream, with cleanup, volume root/capacity checks, a missing directory, local queue overflow/limit reporting and cancellation/disconnect. A unit test checks thread error-mode restoration after an unwind and drive queries. Pure tests cover extended paths, native names, skip decisions and malformed enumeration buffers. A binding-defined aligned-buffer fixture passes equal-size zero-ID files through the actual parser into the index: both are kept and charged individually in both metrics, including known-zero sizes, while nonzero IDs retain their high 128-bit portions and repeated valid IDs still share one charge. This simulates unsupported-provider metadata; it is not a runtime reproduction on an installed filesystem. These checks do not prove whole-volume totals, no-cloud-recall behavior, UI responsiveness, graphical compatibility, physical attribution, native volume-composition behavior or portable distribution.
