# Core contract

The library separates the in-memory `index`, `filter`, `scan`, `synthetic` and `treemap` modules from the Windows metadata engine (`scan_win`) and drive queries (`volume`). The engine reads directory metadata, never file contents. The separate egui/eframe 0.35.0 desktop consumer remains independent of these engine APIs.

## Metadata index

`Index` stores a flat, append-only list. Each entry has an opaque ID, a parent, one native name, kind, optional logical/allocated byte counts, optional file identity and a pending/complete/partial/inaccessible/stale state. IDs belong to one index snapshot; they are not persistent identifiers and must not be carried across snapshots. A scanner/UI transport must validate the owning scan generation before passing IDs to an index.

An entry can only be appended below an existing directory. Its name is one component, not an absolute path: empty names, `.`/`..`, NUL, separators, colons and names longer than 255 UTF-16 units (the Win32 maximum component length) are rejected. Native Windows names that are not valid Unicode remain intact. The index does not duplicate full paths or expose mutable entries.

`summary()` returns:

| Field | Meaning |
|-|-|
| `files` | Visible file entries, hardlinks included |
| `known_logical_bytes` | Sum of every visible file entry with a known logical size |
| `unique_logical_bytes` | Logical bytes charged once per file identity |
| `shared_logical_bytes` | Logical bytes of later hardlink entries that were not charged again |
| `unknown_size_files` | Files whose logical size is unknown |
| `complete` | Every entry is `Complete`; unknown sizes also clear it |

The byte sum alone is never a claim of completeness. Zero-byte files and files with unknown sizes remain distinct. Overflow returns an error instead of wrapping or saturating.

Logical bytes count each visible hardlink entry in `known_logical_bytes`. `unique_logical_bytes` charges a file identity at the first entry that has that identity and a known logical size; later links only add to `shared_logical_bytes`. A link whose size is unknown does not consume the charge for its identity. Identity-less files, such as on a filesystem without stable file IDs, are counted individually. Consequently `known_logical_bytes == unique_logical_bytes + shared_logical_bytes` when no sum overflows. None of these values is physical, allocated or recoverable space, and directory-provided sizes are not added again to the file total.

The index maintains these totals as entries are appended, so `summary()` does not walk the entries. Keeping them current costs one set entry per charged file identity and a count of incomplete entries.

## Name and logical-size filter

`Filter::parse` either creates a complete valid filter or returns a typed error. A consumer must keep its previous valid filter when parsing fails. `evaluate` returns `Yes`, `No` or `Unknown` for one file; directories are context for matching descendants, not independent file matches. Filtering never changes the index or decides what gets scanned.

| Expression | Meaning |
|-|-|
| Empty | All files |
| `*.jpg` | Whole file name ending in `.jpg` |
| `|*.jpg` | Exclude those names |
| `>100mb` | Logical size strictly greater than 104857600 bytes |
| `*.jpg;>1mb` | A JPG with logical size strictly greater than 1048576 bytes |
| `*.jpg;*.png;>1mb;|draft*` | JPG or PNG, larger than 1 MiB, excluding names starting with `draft` |

Positive name masks are OR-ed. Every exclusion and every size condition must also pass. `*` matches zero or more characters, `?` exactly one Unicode scalar. ASCII letters are case-insensitive; other Unicode characters compare literally. This is not a claim of Windows-wide Unicode case folding. If a native name cannot be represented without loss, a name-dependent result is `Unknown`. A conclusive failing size or name condition still returns `No`.

Size conditions accept `<` or `>`, a non-negative decimal integer and `b`, `kb`, `mb`, `gb` or `tb` (case-insensitive). These legacy suffixes use powers of 1024; they do not mean decimal SI units. Comparisons are strict. The metric is always **logical bytes** in this first unit, not an implicit choice between logical and physical size. Unknown size returns `Unknown` when the other conditions do not rule the file out.

The parser accepts outer whitespace on each condition. It rejects empty conditions between separators, missing/unknown units, overflow, fractional/negative thresholds, paths, tag/attribute/date operators and unsupported syntax. An expression is limited to 4096 UTF-8 bytes and 64 conditions. It does not use regular expressions or expand filesystem paths. Literal name characters other than the reserved operators retain their literal meaning.

The desktop binary uses this result to highlight matches, dim non-matches and distinguish unknown decisions without changing geometry or totals. Directories keep the strongest descendant result as context (Yes, then Unknown, then No). Invalid input keeps the last valid highlight. Filtered geometry with separately labelled totals is not implemented.

## Scanner contract

A producer emits a `ScanEvent` tagged with a `ScanGeneration`. Node keys are opaque `NodeKey` values, local to that generation. The payloads are plain data: no `EntryId`, `io::Error`, closures or shared references, so a future elevated NTFS worker can send the same events over IPC while the UI process keeps the index.

Each `ScanRecord` carries a key, an optional parent key, one native name, kind, optional logical/allocated sizes and an optional file identity. The root record has no parent and must be a directory. The producer must emit a parent before its children. A record whose parent is unknown is counted as an unknown-parent diagnostic and is not buffered for later resolution; the same applies to a duplicate key. The consumer never panics on malformed records and never silently discards them.

The record contract has no attribute field. The Windows engine classifies attributes and reparse tags internally without changing the transport; its separate counts-only `ScanReport` exposes skipped entries and degraded enumeration.

Events are:

| Event | Meaning |
|-|-|
| `Batch` | Records, capped by entry count and estimated payload bytes |
| `DirectoryDone(key)` | That directory's immediate children were enumerated; not its complete subtree |
| `DirectoryFailed { key, code }` | The directory could not be enumerated; `code` is producer-defined |
| `Progress` | Coalescable activity counters; no total or percentage |
| `Terminal(Finished/Cancelled/Failed(code))` | Exactly one, after all producer work |

Batches are capped by `MAX_BATCH_RECORDS` and `MAX_BATCH_BYTES`, and the channel is a bounded `sync_channel`. The only exception is a single record larger than `MAX_BATCH_BYTES` on its own: an empty batch accepts it instead of dropping it. Producers send essential events with a retry loop that checks an `AtomicBool` cancellation flag and stops on receiver disconnect. Progress may be dropped when the queue is full because it is coalescable. The terminal event is sent once even after cancellation and blocks while the queue is full. A consumer that requests cancellation must keep draining until it observes that terminal or a disconnect, or drop the `Receiver`; otherwise a producer blocked in that send never returns.

`ScanGeneration` only separates sessions. It does not authenticate a producer and is not a security control. Nothing here defines an IPC transport: before one exists, the consumer must enforce a total node and byte budget for the whole scan, a maximum component length of 255 UTF-16 units and an authenticated, restricted channel. Per-batch caps bound one message, not the index.

`ScanReducer` owns one fresh index for its generation and maps node keys to entry IDs. Events from another generation are counted as stale and ignored before their keys are resolved. `drain` applies whole batches up to a record budget plus bounded control events. `drain_budgeted` instead caps the event count and checks elapsed time between events, always allowing one event to make progress. A whole batch is indivisible and may exceed that time budget. The reducer tracks pending directories. On `Cancelled`, `Failed` or a disconnect without a terminal, every still-pending directory becomes `Partial`; on `Finished` the same transition exposes a producer that omitted a directory outcome. A channel that closes before any terminal is reported as `missing_terminal`.

`ScanDiagnostics` counts stale generations, unknown parents, duplicate keys, invalid records, unknown directory outcomes, duplicate directory outcomes, events after the terminal, partial directories, directory failures and a missing terminal. The last directory failure code is retained for a status line. These counters are protocol evidence, not filesystem errors.

## Windows metadata engine

`run_win_scan(generation, root, sender, cancel)` uses two directory workers by default and returns `ProducerOutcome`. `run_win_scan_with_options` also returns a counts-only `ScanReport`; it accepts 1–8 workers, a shared queue of 1–1024 directories and a local stack of 1–4096 directories per worker. Defaults are 2/1024/4096. When the shared queue is full, a discovering worker keeps work locally instead of blocking other producers. Only exhaustion of both bounds skips a subtree, with `LOCAL_STACK_LIMIT_CODE`; the report records limit hits and observed maximum queue/local depths. Pending work stores native paths, each bounded by the extended Win32 path limit, not an unbounded tree. The consumer's index still needs its own total budget.

The primary path opens **directories only** with `CreateFileW`, `FILE_LIST_DIRECTORY | FILE_READ_ATTRIBUTES`, all three share modes, and `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_OPEN_NO_RECALL`. Root ancestors are checked once with `GetFileAttributesW`; each queued descendant rechecks only its final component before opening, since its parent was already inspected. These are observations, not a race-proof guarantee. Then `GetFileInformationByHandle` and `GetFileInformationByHandleEx(FileAttributeTagInfo)` recheck the opened directory. `GetFileInformationByHandleEx(FileIdExtdDirectoryInfo)` enumerates children in a 64 KiB, 8-byte-aligned buffer. The parser checks header/tail bounds, UTF-16 byte length and aligned, forward `NextEntryOffset` values. `ERROR_NO_MORE_FILES` is the normal end, not every failed call.

Each child receives the directory's volume serial plus its 128-bit file ID as identity, `EndOfFile` as logical size, and `AllocationSize` as allocated size. Negative sizes stay unknown. Files are not reopened. Hardlink identity is charged once by the index; with parallel enumeration, which name gets the first charge is not deterministic. Allocated bytes are metadata observations, not recoverable space or a reconciliation with volume-used bytes; compressed/sparse/ADS accounting has not been validated.

Unsupported operations (`ERROR_INVALID_FUNCTION`, `ERROR_NOT_SUPPORTED`, `ERROR_INVALID_PARAMETER`) before the first successful enumeration buffer use `FindFirstFileExW(FindExInfoBasic, FindExSearchNameMatch)` and `FindNextFileW`, without a per-file open. The fallback reports its count and last triggering code. It preserves logical size but returns **identity=None, allocated=None**, because `WIN32_FIND_DATAW` provides neither. A failure after entries were emitted does not restart enumeration and duplicate records. Empty wildcard results are accepted only after checking the directory again. Access denied (5), file/path not found (2/3), sharing violation (32) and other errors become `DirectoryFailed` with the original Win32 code, never a silently empty directory.

Names stay native `OsString`/UTF-16, including unpaired surrogates. Dot entries are omitted; invalid index components (including over 255 UTF-16 units) are counted in `invalid_names`. FFI paths are absolute and use `\\\\?\\` (or `\\\\?\\UNC\\`), allowing paths beyond 260 characters without relying on the registry opt-in. Device namespaces are rejected. The root record uses its last valid component, or `Volume` for a drive/share root; callers retain the actual selected path separately.

No reparse entry is traversed. Cloud tags `IO_REPARSE_TAG_CLOUD` through `CLOUD_F`, or either `FILE_ATTRIBUTE_RECALL_ON_OPEN` / `FILE_ATTRIBUTE_RECALL_ON_DATA_ACCESS`, conservatively prevent opening/traversal. The shared EA/RECALL_ON_OPEN bit alone is treated as a safety exclusion, not proof that an entry is cloud-backed. Skipped records have unknown sizes. Skipped directories get a coded outcome; skipped files are counted in the report because the unchanged protocol has no file-failure event:

| Constant | Code | Meaning |
|-|-|-|
| `SKIP_REPARSE_CODE` | `0xFFFFFE01` | Not followed: reparse point or observed reparse ancestor |
| `SKIP_CLOUD_CODE` | `0xFFFFFE02` | Not opened: recall attributes or cloud tag |
| `LOCAL_STACK_LIMIT_CODE` | `0xFFFFFE03` | Not enumerated: both traversal bounds exhausted |
| `UNSUPPORTED_PLATFORM_CODE` | `0xFFFFFE04` | Windows APIs unavailable on this platform |
| `WORKER_FAILED_CODE` | `0xFFFFFE05` | A worker could not start or panicked |

The reducer currently maps every `DirectoryFailed` to `Inaccessible`; a consumer must interpret these producer-defined codes as **not followed**, not necessarily a permission failure. Keep the report alongside the snapshot so file skips, invalid names, fallback and resource-limit truncation remain visible.

Parents are appended under the shared output lock before their children can be scheduled. Descendants acquire the same lock, so a parent always precedes them within or across batches without forcing a flush for each directory. The root is flushed once before workers start. Batches flush at about 2000 records, the protocol byte cap, 40 ms of active record production, or a directory outcome. This is not a wall-clock latency guarantee across synchronous I/O. Cancellation is checked per directory/entry, before enumeration calls and in a `try_send` retry loop; disconnect wakes/stops workers. Idle workers use a 10 ms timed condition-variable wait because callers only own an `AtomicBool`; observing cancellation notifies the other waiters, and idle cancellation wakeups are counted. In-flight synchronous calls have no cancellation deadline. Exactly one terminal send is attempted **after every worker joins**, including cancellation; it retains the existing drain-or-drop requirement under backpressure. A failed terminal can coexist with `ProducerOutcome::Finished`, which denotes transport completion, not successful scanning.

`volume::list_drives` uses `GetLogicalDriveStringsW`, `GetVolumeInformationW` and `GetDiskFreeSpaceExW`. Unqueryable drive roots remain in the list. Label, filesystem, total bytes and free bytes are independent `Option` measurements: a failed capacity query does not erase a known label, and `Some(0)` free bytes means a full volume, not unknown. `free_bytes` is total free space on the volume, not quota-available space. `volume_root_for` uses `GetVolumePathNameW` and strips the extended prefix from its returned root. Drive queries and each directory worker's full lifetime use a thread-bound RAII `SetThreadErrorMode` guard (`SEM_FAILCRITICALERRORS | SEM_NOOPENFILEERRORBOX`) to suppress removable-device dialogs. It preserves existing mode bits and restores the previous thread mode on return or unwind; it never changes process-global error mode. There is no `WNet*` network discovery; already mapped drives may still appear. Non-Windows drive queries return an unsupported error (`volume_root_for` returns None), and the scanner sends the unsupported terminal.

The only direct binding dependency is `windows-sys =0.61.2`, enabled on Windows. `Win32_Storage_FileSystem` supplies enumeration, handle metadata and volume APIs; `Win32_Foundation` supplies handles, errors, `GetLastError` and `CloseHandle`; `Win32_Security` is required by the binding's `CreateFileW` signature even with null security attributes. `Win32_System_Diagnostics_Debug` supplies `GetThreadErrorMode`/`SetThreadErrorMode` for dialog suppression and restoration. No System_IO, SystemInformation or Console feature is used. Unsafe code is denied crate-wide and allowed only inside `src/scan_win.rs` and `src/volume.rs`, with local FFI safety justifications. CI fails if `allow(unsafe_code)` appears in any other `src` file. Cargo uses `deny`, not `forbid`, because `forbid` cannot be relaxed for these two module-local FFI exceptions.

**Unverified limits:** actual cloud placeholders in an authorized sync environment, provider virtualization modes, network shares, non-NTFS fallback on a real device, access-denied/sharing/removal races, compressed/sparse/ADS attribution, and real >260-character paths with registry opt-out disabled. Pure path tests are not real long-path I/O evidence. `OPEN_NO_RECALL` and metadata-only intent are not certification of no provider fetch. Ancestor checks and final-handle rechecks do not eliminate a path lookup race: an ancestor can be replaced between inspection and `CreateFileW` or path-based fallback enumeration. Adversarial replacement and real sync roots remain unverified; no race-proof/no-hydration guarantee is claimed. No whole-volume scan is part of the engine tests.

## Synthetic producer

`synthetic` implements a deterministic producer over the same channel and reducer. A `SyntheticSpec` fixes the root name, directory/file counts, inaccessible directories, hardlink pairs, unknown-size files and progress interval. SplitMix64 derives every choice from the seed, so the same seed produces the same records, names, sizes and identities.

The producer emits the root first, then parents before children, reports inaccessible directories with a synthetic code that is not a Win32 error, and shares file identities for hardlink pairs. It sends a final progress summary before its terminal, even when the periodic interval is zero. It builds its plan in memory and does not touch a disk. It is a contract and layout fixture, not the filesystem scanner.

## Treemap layout

`treemap::layout` is pure. It takes an index, a subtree root, a rectangle and `LayoutParams { min_pixel_area, header_height }`, and returns placed cells. It does not measure text, draw or depend on egui.

Weights are integer logical bytes. The first entry with a file identity and a known size charges those bytes; later links have zero weight, so a hardlink is never charged twice. Unknown logical sizes get no area and set `has_unknown`. Known zero-byte entries also get no cell. Every placed node reports `known_sum` and `has_unknown`, and the root reports the subtree totals.

Siblings whose expected area is below `min_pixel_area` are grouped before squarification into one `NodeRef::Aggregate { parent }` cell. The aggregate keeps the member entry IDs, so it remains navigable, and its weight is the sum of its members. A directory cell shows a header when its height is at least twice `header_height`; otherwise the header collapses and the whole rectangle is content, and a `header_height` of zero disables headers. Child rectangles tile the parent's content rectangle, with area proportional to known bytes.

A directory whose subtree holds no charged bytes gets no cell. A folder that only holds unknown sizes, inaccessible content or later hardlink names stays in the index and keeps its unknown flags, but the map offers no area to open. This is the current behavior; whether such folders deserve a navigable zero-area cell is a product decision pending window review.

Both the children map and the subtree totals are rebuilt on every call, and hardlink charging uses one entry per identity. That keeps `layout` pure and O(n) per call: a caller that redraws should cache the layout per index version instead of recomputing it every frame.

Squarification accumulates in `f64` and converts to `f32` at the boundary. The order is deterministic: size descending, then native name, then entry ID. Layout descends iteratively, only into directories whose content area reaches `min_pixel_area`; a deep tree does not use call-stack recursion. Invalid geometry, invalid parameters, an unknown root and size overflow return typed errors instead of producing bogus rectangles.

`layout_members` opens an aggregate's selected siblings using their original IDs and descendant trees, without unrelated siblings. Members must be nonempty, distinct and immediate children of the supplied parent; invalid selections return `UnknownRoot`. The root cell is the parent context, but its totals cover only the selected members. Further aggregates keep their members and remain navigable. The desktop lowers the grouping threshold in detail views so at least one member can expand on each visit.

Volume composition is not implemented: free and unattributed space need volume capacity and accounting data that this unit does not receive. The layout only tiles the known scanned bytes.

## Desktop consumer

The default `desktop` Cargo feature enables optional eframe for `src/main.rs` and `src/ui/`; the library modules never import it. `cargo test --locked --no-default-features` tests the core and Windows engine without GUI dependencies. The Windows-only binding dependency remains available without `desktop`.

The window opens a drive/path chooser without starting a scan. Its drive choices come from a single background `list_drives` task, showing “Listing drives…” while it runs. Results are cached for the session and reused when reopening; Refresh drives explicitly updates them, with at most one listing task in flight. Enumeration errors are shown without inventing capacities. Each available capacity is displayed independently, including zero free bytes. A selected path must pass `std::fs::metadata` as an existing directory. Prefixes are first inspected with `symlink_metadata` to reject observed symlinks/junctions and reparse ancestors without canonicalizing through them. These checks retain the engine's concurrent path-replacement limitation.

Starting a real scan cancels and retires the previous producer without joining an unfinished thread. Repeated requests coalesce into one latest request; no replacement starts until the retired producer returns, so at most one producer is active or retired. A separate preparation task validates the path, queries `volume_root_for(selected_path)` and lists drives again before launching the scanner, so the header's label and free/total bytes come from a current query rather than the chooser's session cache. That keeps the first Start working while its initial listing is still running and gives a rescan current capacity instead of one captured earlier. “Checking path and volume…” remains visible during preparation, and invalid paths return to the chooser. The generation then increments and a named thread runs `run_win_scan_with_options` with default options over `sync_channel(DEFAULT_CHANNEL_CAPACITY)`. The reducer, navigation history, selection and layout cache are reset. The chooser closes, and the header displays the volume root/label and queried free/total bytes separately from map bytes. If lookup fails, the header keeps the selected root with unknown capacity. File → Explore synthetic sample uses the separate generated fixture, explicitly labelled as a sample with no capacity data. F5 and Rescan repeat the selected scan root or sample, not the currently zoomed folder, and never silently substitute the sample for a real path.

The consumer drains up to 64 events or about 2 ms per frame, checking time between whole events; one batch can exceed the time budget. It keeps the channel bounded, signals cancellation and drops the receiver before retiring a replaced or closing producer, so a terminal send cannot deadlock shutdown. It polls `is_finished()` and joins only finished threads, including during Drop. “Stopping…” is shown while cancellation or replacement waits. A close request with threads still running is held for up to two seconds while the window keeps repainting, so returnable work finishes on its own; if a thread is still blocked after that, the window closes and Drop detaches it, so a path stuck in synchronous I/O cannot require killing the process. An in-flight synchronous Win32 call cannot be interrupted or given a deadline: it can delay a replacement or the close hold, but the UI thread does not wait in `join`. Forced teardown detaches unfinished handles rather than blocking Drop; they end when the process exits. Cancel sets its flag and visible lifecycle immediately while draining continues, and Escape or the chooser's Close while a path is being prepared also cancels that preparation. Lifecycle (Scanning, Finished, Cancelled, Failed) is separate from metadata completeness; unknown sizes and inaccessible directories do not turn a finished producer into a partial lifecycle.

Layout is cached by consumed-event version, navigation and viewport rectangle, at most four rebuilds per second while scanning. Hover and selection reuse geometry and fitted labels. Navigation stores native name components and aggregate member names in memory, not snapshot IDs, so locations can be resolved against an index without retaining its IDs. Starting or rescanning a dataset clears history and selection.

The window opens in the dark theme unless a saved choice says otherwise; both are fixed palettes, independent of the system preference. View → Dark/Light switches between them in place. The stored choice is applied before the first frame, and eframe keeps the native window hidden until that frame is painted, so a saved light theme does not flash dark. Both menu items are selectable, so AccessKit reports the active one as toggled. Theme colors are resolved only when painting and in egui's visuals; layout parameters, header height and label fitting do not read them, so both themes produce the same rectangles and labels, and switching themes never rebuilds the cached layout. Cached cells store what an entry is (directory depth, file, aggregate, incomplete state), not colors. Some states also carry a mark that does not depend on hue: a dashed inner border for partial entries, a dotted inner border for aggregates at least 24 px on each side, and a dotted header rule when a folder's total is incomplete (`has_unknown`: unknown sizes, or partial or unreadable content below it). Marks are skipped on cells under 8 px. Directories, files, non-matching entries and unknown filter decisions are told apart by fill only. The painter also hatches inaccessible entries and gives stale ones the dashed border, but the current product never shows either: an inaccessible directory has no known bytes and so no cell, and nothing produces the stale state yet. Leaf cells get a 1 px seam in a darker shade of their own fill, omitted on non-matching cells. Hover (1 px), selection (2 px, stronger contrast than hover on every fill) and keyboard focus are outlines, so they never replace the state fill; on cells under 8 px hover and selection are drawn outside the cell. Focus is a two-tone dashed ring outside the control.

Only window geometry and the theme are persisted by eframe in its application-data directory. The theme is one plain string under the `theme` key, written as `v1:dark` or `v1:light`; a missing, unknown, future-version or corrupt value falls back to dark rather than guessing. Egui memory persistence is disabled, so egui's widget and in-app window state is not stored, and names, filters and navigation are never serialized. AccessKit is enabled; map cells expose accessible labels, selection and focus. Backspace goes up, Alt+Left/Right moves through history and Escape cancels a scan; while the highlight field has focus, Escape leaves the field and the scan keeps running. Text editing retains its navigation keys. The status line shows the dataset root and the native path components, and appends the small-item count when the map shows an aggregate's members. In that member view the root cell keeps the parent directory's name and adds the same subset count, so its totals are not mistaken for the whole folder.

The consumer retains the engine's returned counts-only `ScanReport` in memory and appends it to the status tooltip and the status area's AccessKit label once the producer returns: fallback directories (and the last triggering code), reparse/cloud skips, invalid names, stack-limit hits, maximum queue/local-stack depth and cancellation wakeups. While scanning, the report is not yet available; a sample has no engine report. A failed terminal or drive-query `ScanError` is shown as a readable message. Producer-defined safety/resource codes retain their documented meanings rather than being described as permission errors; other Win32 codes read `error N`, and a drive-listing failure states its numeric code once as `code N`. Ordinary directory failures, including the latest code, remain in that full status detail instead of leaving a permanent red fatal-error message; terminal failures, missing-terminal disconnects and producer panics use the error line. The status area's AccessKit label repeats that full detail after the visible status text, without changing its fixed height. The highlight counter is shown only when the trimmed filter text is nonempty, following the parser's blank-expression rule. Producer completion is polled without joining an unfinished thread in the per-frame drain; no report is fabricated while it is running.

Free-space and not-yet-scanned map blocks, saved snapshots, export and alternate view modes are not implemented. The corresponding unavailable controls do not imply those capabilities exist; only the nested logical-byte map is active.

An error returned by `eframe::run_native` prints a clear message to stderr and returns exit code 1. There is no native message box, graphics fallback or claim that upstream graphics panics are caught. Real-driver fallback, DPI coverage and full accessibility testing remain separate checks.

## Verification boundary

Integration tests call the public index, filter, scan, synthetic and treemap API with synthetic metadata and fixed expected answers. They cover the filter grammar, unknown values, native Windows names, hierarchy, component length and overflow; scan generations, parent order, batching caps, cancellation under backpressure, a dropped receiver after cancellation, duplicate keys, invalid records, unknown directory outcomes, disconnect without terminal, inaccessible directories, hardlinks, unknown sizes, terminal handling and determinism; and layout containment, sibling disjointness, area conservation, proportionality, headers, aggregation, unknown sizes, determinism and a deep tree.

`tests/navigation.rs` also exercises history across new snapshots, aggregate locations, hit testing, measured-width label fitting, highlight decisions, invalid-filter retention and lifecycle states through the binary's pure logic module. `tests/aggregate_navigation.rs` checks aggregate member layouts through the public treemap API. Unit tests in `src/ui/theme.rs` check both palettes' contrast, each theme overriding a different system preference, and the stored preference read and written through `eframe::Storage`. UI boundary tests also check real volume-to-choice mapping (including unknown capacities), existing-directory validation and producer-code messages. Headless egui tests do not establish native-window behavior.

Windows engine tests also scan only small temporary fixtures: nested and empty directories, known file lengths, Unicode names and hardlinks, with cleanup, volume root/capacity checks, a missing directory, local queue overflow/limit reporting and cancellation/disconnect. A unit test checks thread error-mode restoration after an unwind and drive queries. Pure tests cover extended paths, native names, skip decisions and malformed enumeration buffers. These checks do not prove whole-volume totals, no-cloud-recall behavior, UI responsiveness, graphical compatibility, physical attribution, volume composition or portable distribution.
